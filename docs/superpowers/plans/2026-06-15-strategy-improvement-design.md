# 매수·매도 전략 개선 설계안 (2026-06-15)

> 상태: **설계(Plan) 단계** — 코드 변경 전 승인용. 구현은 단계별 1개씩, 각 단계마다 백테스트 검증 게이트 통과 후 다음 단계 진행.

## 0. 근거 데이터 (추측 아님, 저장된 백테스트 결과)

`data/actual_exit_strategy_stress_matrix_2026-05-19.csv` — 동일 구간·동일 유니버스, top_n=20, weekly:

| 설정 | 총수익 | CAGR | MDD | Sharpe | 승률 | 거래수 |
|---|---|---|---|---|---|---|
| custom cost, **stops ON** (현재) | 88.14% | 30.44% | -18.37% | 1.3975 | 54.65% | 1049 |
| custom cost, **stops OFF** | 166.01% | 50.89% | -21.55% | 1.5301 | 44.40% | 520 |

핵심 해석:
- 스톱을 끄면 **수익 2배, Sharpe 상승(1.40→1.53), 거래수 절반(비용↓)**, 대가는 MDD -18.4%→-21.6% (3.2%p)뿐.
- 즉 현재 청산 캐스케이드가 **회복할 승자를 조기 청산(whipsaw)** 하고 있음. 승률은 stops ON이 높지만(54.7%) 평균 손익비가 나빠 총수익이 낮음 — 전형적 "이익은 짧게, 손실은 자주" 패턴.
- 청산 사유 로그(`adaptive_alpha_backtest`): `rebalance 360`, `stop_loss 141`, `profit_take 133`, `post_profit_trailing 102`, `atr_stop 70`. 고정 스톱+트레일링이 청산의 다수.

결론: **스톱을 끄는 게 아니라(테일리스크 방어는 유지), 더 넓은 ATR 단일 스톱으로 재설계**해 whitesaw를 줄이고 stops-OFF의 수익/Sharpe에 근접시킨다.

## 현재 청산 캐스케이드 (코드 기준)

`src/backtest/engine.py` L549–586, `src/trading/engine.py:check_exit_rules`, `config.py:ExitRulesConfig`:

진입가 대비 매 리밸런스 점검 시(profit_take 전):
1. **ATR 스톱**: `close <= entry - ATR×2.2` → 전량 매도
2. **고정 손절**: `return_from_entry <= -7%` → 전량 매도
3. **익절**: `return >= +16%` → 45% 매도, 잔량을 트레일링(50%)+브레이크이븐(50%) 버킷 분리
익절 후:
4. 트레일링 버킷: `고점대비 <= -10%` → 매도
5. 브레이크이븐 버킷: `진입가 대비 <= 0%` → 매도

문제: (1)과 (2)가 **이중 손절**이고, -7% 고정 스톱이 ATR보다 먼저/타이트하게 걸려 변동성 큰 종목을 조기 청산.

## 단계 1 — 청산: ATR 단일 스톱으로 완화 (최우선)

### 목표 (검증 가능 형태)
"고정 -7% 손절과 트레일링 -8%를 제거하고, ATR 배수만으로 손절을 통제한다. 백테스트에서 동일 구간 stops-OFF 대비 Sharpe 격차를 절반 이하로 줄이고, MDD는 stops-OFF보다 낮게 유지한다."

### 변경 설계
1. **고정 손절 제거**: `stop_loss_pct` 경로(`engine.py` L568-569)를 ATR 스톱이 있을 때 비활성. ATR이 없는 종목(데이터 부족)만 폴백으로 고정 스톱 유지 → 안전망.
2. **ATR 배수 확대 탐색**: 현재 `atr_multiplier=2.2`. 2.5 / 2.8 / 3.0 / 3.5 그리드 백테스트. 더 넓은 스톱이 whipsaw를 줄이는지 확인.
3. **트레일링 단순화**: 익절 후 2버킷(트레일링+브레이크이븐) 구조를 **ATR 기반 chandelier 트레일링 단일화** 검토 — `고점 - ATR×k`. 브레이크이븐 버킷이 +0% 복귀 시 잦은 청산을 유발하는지 로그로 확인 후 결정.
4. **파라미터는 config로만** (CLAUDE.md 규칙: 매매 동작 영향 파라미터는 config에). `ExitRulesConfig`에 `atr_only_stop: bool`, `chandelier_atr_multiplier` 추가.

### 데이터 기반 의사결정 절차
- `scripts/run_backtest_matrix.py`를 atr_multiplier 그리드로 실행 → CSV 비교.
- 기준: Sharpe ↑ AND 거래수 ↓ AND MDD ≤ 현재 stops-OFF(-21.6%). 세 조건 동시 충족 조합 채택.

### 검증 게이트
- ATR 스톱/청산 관련 단위 테스트 (`tests/`의 stop 시뮬 테스트) 통과.
- 백테스트 회귀: 신·구 설정 동일 구간 비교표 생성, Sharpe/MDD/거래수 명시.
- `python -m compileall` + 관련 pytest 통과.

## 단계 2 — 진입 타이밍 필터 강화

### 현황 (코드 기준)
`src/factors/scoring.py:_apply_buy_candidate_filters` + `technical_hard_filter`: 하드필터는 `RSI≥90 & MA20대비 +20% 이상 과열` 또는 `일변동성≥8%`만 배제. 즉 **극단값만 컷**, 일반적 고점/약추세 매수는 통과.

### 목표
"진입 시점에 추세·거래량·갭 조건을 추가해, 백테스트에서 진입 직후 손절 비율(stop_loss 청산/총진입)을 낮추고 승률 또는 손익비를 개선한다."

### 변경 설계 (요청 3개 영역 중 진입)
1. **추세 확인 필터**: 진입일 종가 > MA20 **그리고** MA20 > MA60 (정배열)만 신규 진입 허용. 약추세 진입 차단.
2. **거래량 확인**: 최근 거래량 ≥ N일 평균(이미 `_latest_to_average_ratio` 존재) — technical_score 가점이 아니라 **하드 조건**으로 승격 옵션 검토.
3. **갭 필터 연동**: `PORTFOLIO.max_abs_open_gap_pct=0.20`가 라이브엔 있으나 백테스트 진입엔 미반영. 진입 당일 과도한 갭상승(예 +10%↑) 종목 진입 보류.
4. 필터는 **점수 가점이 아닌 진입 게이트**로 추가하되, 후보가 top_n 미만으로 줄면 차순위로 채우는 폴백 유지(과도한 현금화 방지).

### 검증 게이트
- 진입 필터 단위 테스트(통과/탈락 케이스) 작성 후 통과.
- 백테스트: 필터 ON/OFF 동일 구간 비교, stop_loss 청산건수·승률·Sharpe 변화 측정.

## 단계 3 — 팩터 가중치 워크포워드 재최적화

### 현황
`config.py:FactorConfig` 100점 예산: Value 25 / Quality 25 / Momentum 20 / Yield 5 / Technical 15 / Auxiliary 10. `scoring_method="rank"`. 이 배점은 매트릭스 최적화가 아니라 설계상 고정값.

### 목표
"과적합 없이 팩터 배점을 재탐색한다. In-sample에서 고른 가중치가 Out-of-sample에서도 벤치마크 대비 우위를 유지하는 조합만 채택한다."

### 변경 설계
1. **워크포워드 분할**: 예) 학습 2020–2023 / 검증 2024–2025-06 / 홀드아웃 2025-07–현재. DB 가격범위 2009–2026 확인됨 → 분할 충분.
2. **탐색 공간 제한**(과적합 방지): 각 팩터 ±10점 범위, 합 100 고정, 격자 거칠게(5점 단위). 무차별 미세조정 금지(CLAUDE.md "단순함 우선").
3. **선택 기준**: 검증 구간 Sharpe 상위 + 홀드아웃에서 벤치(`069500`) 초과 동시 충족. In-sample만 좋은 조합은 폐기.
4. `scoring_method` zscore vs rank도 같은 프레임으로 비교(현재 rank가 로컬 DB 아웃라이어에 강건하다는 주석 근거 재확인).

### 검증 게이트
- 점수합=100, 0–100 범위 계약 테스트 유지(기존 Phase2 테스트).
- 워크포워드 결과표(학습/검증/홀드아웃 각 구간 지표) 산출, 채택 근거 문서화.

## 단계 4 — 포지션 사이징 / 집중도

### 현황
`PortfolioConfig`: n_holdings=30, score_weighted, 비중 3%–15%(어댑티브는 3%–10~12%). 비중이 **점수 비례**일 뿐 변동성 미반영. 스트레스 매트릭스에서 **top_n=20이 30보다 Sharpe 우수**(여러 리포트에서 top_n=20 best).

### 목표
"종목 비중에 변동성을 반영하고 보유종목 수를 데이터로 재선택해, MDD 대비 수익(Sharpe/Calmar)을 개선한다."

### 변경 설계
1. **변동성 타깃 비중**: 비중 ∝ score / 변동성(역변동성 가중). 변동성 큰 종목 비중 자동 축소 → 단계1 스톱 완화와 보완 관계(스톱 넓힌 대신 사이징으로 리스크 통제).
2. **top_n 재선택**: 20 / 25 / 30 그리드. 다수 리포트가 20 우위 → 20을 1순위 후보로 검증.
3. **비중 상·하한 재설정**: 변동성 가중 도입 시 max를 10~12%로 낮춰 집중 리스크 제한, min은 거래비용 대비 의미 있는 수준 유지.
4. 시장과열/매크로 현금 오버레이(`MarketRiskConfig`,`MacroRiskConfig`)는 **이번 범위 외** — 단계1–4 안정화 후 별도 검토.

### 검증 게이트
- 사이징 함수 단위 테스트(역변동성 가중 합=1, 상하한 클램프) 통과.
- 백테스트: 사이징 신·구 비교, Sharpe·Calmar·MDD 측정.

## 통합 실행 순서 & 안전 원칙

1. 단계1(청산) → 2(진입) → 3(팩터) → 4(사이징). **한 번에 하나**, 각 단계 검증 게이트 통과 후 다음.
2. 모든 변경은 **PAPER/무주문 백테스트로만 검증**, 라이브 주문 경로 무변경.
3. 매 단계: 변경 전후 동일 구간 백테스트 비교표를 `data/`에 CSV+MD로 남김(기존 컨벤션).
4. 누적 효과는 단계4 종료 후 **전체 회귀 백테스트** 1회로 최종 확인.
